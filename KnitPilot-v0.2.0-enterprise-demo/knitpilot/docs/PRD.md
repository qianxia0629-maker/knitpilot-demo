# KnitPilot / AI针织工艺师 · 产品需求（V1）

## 1. 用户与问题

面向针织服装厂工艺师、审核工艺师和 QC。用户上传款式图、尺寸表、历史工艺单和 QC 修改单，核对抽取的数据，生成可人工审核的圆领套头衫工艺初稿。现有重复录入和手工换算耗时，历史款修改难追踪，漏检针数守恒会造成返工。

成功指标：在真实样本上记录从上传到可审核初稿的耗时、必填字段确认率、QC 召回率、审核后修改次数；须由工厂确定基线与验收阈值，不能在未验证前宣称准确率。严禁未经工艺师确认直接用于生产。

## 2. V1 工作流

1. Dashboard 创建项目，选择基础圆领套头衫、长袖、正肩或基础落肩，尺码独立成版。
2. 上传图片/PDF/表格，保存文件来源和页码；OCR/视觉识别/历史检索只生成带证据的字段候选。找不到的值为 `null`，不可猜测。
3. Extraction Review 展示 `value/unit/source/confidence/confirmed`；工艺师核对款式、机台针数范围、纱线、密度、横纵缩水率和每一个尺寸；低置信度提示复核。缺失或未确认的计算输入阻止生成。
4. 引擎以洗后目标尺寸、洗前密度、缩水率反推织造尺寸，合法化针数，生成前后片、袖片和领条的基础工艺与行数。所有数值和规则都由确定性代码决定。
5. 编辑器左侧部件导航，中部程序生成 SVG 技术图，右侧对应参数；袖窿点击显示起始行和收针，领口显示中间平收和两侧减针。自然语言编辑先转换成受限 operation，再由引擎全量重算。
6. QC 展示通过/失败/需人工判断及算式证据；不通过不得标记 final。人工审核并记录版本、修改者、原因和时间。
7. 导出 PDF 和 Excel，含规格、假设、QC、版本号和审核信息。V1 仅为工艺初稿，不输出机器程序。

## 3. 支持矩阵

| 范围 | V1 |
| --- | --- |
| 款式 | 基础圆领套头衫，长袖，正肩，基础落肩 |
| 部件 | 前片、后片、两只同规格袖片、领条 |
| 组织 | 平针；领/下摆 1x1、2x2 罗纹 |
| 计算 | 尺寸转针/转、横纵缩水、均匀加减、基础袖窿/领窝/肩斜/袖山、循环合法化 |
| QC | 起针/加针/减针/平收/余针守恒，前后肩、左右对称、总高/宽、领宽、袖肥、袖山/袖窿、循环和机台范围 |

不支持提花、复杂麻花、复杂镂空、WholeGarment、无缝编织和机器程序生成。款式图不能可靠推导的工艺参数必须由工厂提供。对不同组织的密度应使用实测样布；V1 一个确认的平针密度，不支持复杂混合组织的独立补偿。

## 4. 输入和输出合同

必填：款式、尺码、机台最小/最大允许针数、横/纵密度（针/10cm、转/10cm）、横/纵洗后尺寸变化率、胸宽（平铺单片）、衣长、袖窿深、肩宽、肩斜高、前后领深、领宽、袖长、袖口/袖肥、袖山高、袖山顶宽、下摆/领条高、领条目标长度、循环数、QC 容差。所有尺寸以洗后成衣厘米计；缩水率 -0.05 指洗后缩短 5%。单片尺寸和袖长量法要在工厂验收阶段统一。

字段证据：每一个 AI 识别的原子字段有 `value`, `unit`, `source`, `confidence` (0..1), `confirmed`。自动抽取时 `confirmed=false`；人工确认以后才可计算。原始附件与结构化规格分离存储，保留来源定位和 schema_version。数值限制、量纲核对及确认状态双层校验；用户输入不得借 AI 操作改变计算字段。

输出：合法针数及理论针数、差值/成品宽误差/原因；每一部件的起针、转数、单侧加减针序列、中心平收、最终余针；罗纹、花型循环；可审计 QC 结果。`4-2-3` 为每 4 转每侧减 2 针，重复 3 次，结构为 `{interval_rows:4, stitches:2, times:3}`。袖片两侧对称时共减针数是单侧数的 2 倍。

## 5. 加减针和合法化验收

- 92 转、每侧增加 12 次 → `8-1-8`, `7-1-4`；总 92 转、每侧 12 针，最多两组，组间间隔差不超过一转。左右复用同一序列。
- 如果无事件，允许留空序列；有事件时行数必须至少等于事件数。袖山等不可行尺寸返回明示错误。
- 合法针数同时满足偶数/对称、花型或罗纹循环及机台上下界，取距理论针数最近，等距时取较小值；返回洗后宽度误差，超容差 QC 失败。
- 缩水反推：58 cm、-5% → `58/0.95` cm，再乘密度；不得使用 `58*1.05`。
- 基础袖山/袖窿采用固定明示的几何规则；袖山边长与袖窿边长采用近似比较，并明确要求样衣和工艺师核对吃势与缝合长度。

## 6. 版本、权限和审计目标

目标状态为 `ai_draft`, `manual_revision`, `qc_revision`, `final`。每一次持久化修改追加新版本，保留父版本、不可覆盖快照；`manual_edits` 记录 field_path/old_value/new_value/reason/user/timestamp。导出须引用确定版本。后续多租户须按组织隔离文件、规格和版本，具备编辑、审核、只读权限和导出审计；训练数据只在获得明确授权、去标识化和访问控制后使用。

## 7. 阶段与验收

阶段一：schema、纯 Python engine、确定性 QC、基础 FastAPI 计算/预览 API、单元测试，核心模块分支覆盖率不低于 90%。API 当前只计算和预览，不持久化编辑；预览不可被视为版本提交。

企业试用演示增量：Next.js 手动录入界面、前后片/袖片/领条程序 SVG、计算与 QC 结果、JSON 下载、共享访问码。它使用非敏感示例，不支持上传识别和数据保存。

下一阶段：PostgreSQL 迁移、追加式版本服务、上传与人工确认、历史款检索、AI 接口适配器、个人鉴权、组织隔离与安全审查。再下一阶段：PDF/Excel 导出和工厂验收数据集。正式发布前须对真实工艺单做专家复核，定义各机台工艺参数与容差。
